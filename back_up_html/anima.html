Animaについて

https://huggingface.co/circlestone-labs/Anima
CircleStone LabsとComfy Orgが開発する、アニメイラストに特化したText-to-ImageのMMDiTモデル。NVIDIAのCosmos-Predict2がベースである。

パラメータ数は2Bと現代のMMDiTモデルの中では軽量な方で、VRAM8GBで快適に動作する(だが計算はSDXLより二倍遅い)。

SDXLに対するAnimaの強みは？

  • 水平線やフェンスがずれたり曲がったりといった破綻が少ない。
  • 色が綺麗で明暗の表現がいい。Noob v-predより良い。
  • 細部の描写が良く目などが潰れにくい。
  • 自然言語による位置などの具体的な指示が可能。
  • メモリ使用量がSDXLより少ない。SDXLは6.9GB必要だがAnimaは5.6GBで済む。
    • 学習のコストがSDXLと同等かそれ未満で済む
    • Block Swapを使えば、8GBのVRAMでもTE込みかつ1024pxで学習できる。速度低下も少ない。※TEの学習は特別な理由が無い限り不要
  • Fine-Tuning(学習)が容易。学習効率が良い感じ。
拡散モデル
SDXLは畳み込みニューラルネットワークがベースのU-Netアーキテクチャだが、これは現在主流のTransformerベースのDiffusion Transformer(DiT)を採用する。
DiTは水平線や物体の構造の連続性維持が比較的得意で破綻が少ない。
パラメータ数は2Bと現代のMMDiTモデルの中では軽量な方。SDXLは2.6B。
TE
Text Encoderは、Qwen3-0.6Bの出力をT5XXLにマッピングしており、SDXLのCLIP-L+Gより軽量で高性能。位置や文字などの具体的な情報を解釈できる。
CLIPよりは確実に良いがLLMとしてはかなり弱い。ちなみにより大型のTEにしても元のTE(T5XXL)が弱いからあまり意味がないとか。
VAE
16チャネルのQwen Image(Wan Video)のものを使用し、色精度とディティールがとても良い。かさついた質感がない。目がほとんど崩れない。
その他
メモリ使用量がSDXLより若干少ない。

欠点

  • DiTであるが故に計算が遅い。SDXLの約二倍の時間がかかる。
    • INT8_ConvRot形式のウェイトを使えば精度をほとんど落とさずにSDXLと同等かそれ以上の速度になる。
  • 対応UIが少ない。対応する一般的なUIはComfuUIとForge Neoの二つのみ。
  • 学習解像度を大きく上回る解像度で生成すると出力がモザイク状になる(Cosmos-Predictの仕様)。特に縦長の比率で発生しやすい。
  • TEが軽量だが相応に弱く、文字の描写ととても複雑なプロンプトは苦手。
    • 2026年のMMDiTモデルの中では最弱クラス
  • SDXLよりはマシだが、背景の品質が低い。Animaのパラメータ数が少ないことと、背景まで書き込む絵師が少ないことが原因。
  • 名前があまりにも一般的でweb検索しづらい。AIにAnimaの事を聞くなら、GPT-6などの最新AIにMMDiTのAnimaと言った方がいいかも。
  • 英語のみ対応(T5XXLの仕様)

対応UI

現時点でComfyUIとForge Neo。

動作要件

空き容量20GB以上のSSD推奨。
推論
16GB以上のRAMと最低6GBのVRAMを搭載するfp16対応GPU。bf16対応の8GB以上のVRAMを搭載したGPUを推奨。
LoRA学習
16GB以上のRAMと最低8GBのVRAMを搭載するfp16対応GPU。bf16対応の10GB以上のVRAMを搭載したGPUを推奨。

使用方法(ComfyUI)

Hugging Faceリポジトリから次のファイルをDLして配置する。
ComfyUI/models/diffusion_modelsにanima-〇〇-v1.x.safetensors
〇〇はbase, aethetic, turboのいずれか。baseは基本、aestheticは少し品質が上がったもの、turboは高速な蒸留モデル。

ComfyUI/models/text_encodersにqwen_3_06b_base.safetensors
ComfyUI/models/vaeにqwen_image_vae.safetensors

ComfyUIのテンプレートにAnimaがあるのでそこから生成を始めるといい。

推奨生成パラメータ

  • 解像度: 画素数が1024x1024や832x1216などの104万画素に近似する値
  • Steps: 30-50(実際には20ステップで十分)
  • Guidance Scale: 4-5

その他

公式には書いていないがこれらが良い感じ。
  • Sampler: RES Multistepが無難。ER SDE、Gradient Estimation、SA Solver、Eulerでもよい。
  • Scheduler: Simpleが無難。NormalやSGM UniformでもOK。Linear Quadraticは収束がやや遅いが安定性が高い。
    • KarrasとExponentialは非対応(SDXL以前のepsilonモデル専用)。

Euler ancestralは絵がぼやける傾向がSDXLより強い。Flow-Matchingモデルではeuler aは不向き。

プロンプト

プロンプトはDanbooruタグと自然言語(英語)の両方が使える。位置指定や文字描写などの具体的な命令もOK。
しかし、TEが小型なため正確な位置、順番の指定や文字の描写などの複雑な命令はあまり得意ではない。

1grirl, 〜, outdoors, day...のような単調なプロンプトでは相応に単調な絵になる。ディティールを盛るなら、Danbooruタグと自然言語を組み合わせるのがベスト。
英文が苦手なら翻訳機で「これは~が~しているイラストです。~と~が背景にあります。このイラストは~な雰囲気です。」のような文章を英語にすればいい。チャットボットに考えてもらうのもいい。
画像から自然言語プロンプトを生成するなら、検閲解除版のVLM(Qwen 3 VLやGemma 4など)を使うと良い。

タグは次の並びで学習している。これに従う必要はない(だが推奨)。
quality/meta/year/safety tags, 1girl/1boy/1other etc, character, series, artist, general tags

タグの区切りのコンマとスペースは必ず守ること。コンマだけだと隣接する単語の動作が変化するかタグの効果が低下する。

「1girl, upper body」のようにプロンプトが短すぎると破綻が増加する。

強度指定

Text EncoderはSD1/SDXLで使用されるCLIPではなくQwen3(0.6B)というLLMだが、機能する(T5にマッピングしているから機能する？)。
しかし、SDXLほど効果は強くなく、15倍前後まで強くできる。大体70倍を超えると完全に壊れる。

Flow Shiftの値

ComfyUIのModelSamplingAuraFlowのshiftのこと。
低いほど高周波成分が強くなってディティールが増えるが不安定になる。高いほど安定するが、絵が平坦になる。
Animaの初期値は3。解像度に合わせて高くするといいかも。
例えば1024x1024を1.5倍の1536x1536にアップスケーリングするなら4.5にするとか。
ステップ数が多いほどこの値の影響が小さくなる。ノイズスケジューラにLinear Quadraticを選択しても影響が小さくなる。

ライセンス

CircleStoneLabsの独自ライセンス。独自と聞いて身構えるかもしれないが寛容なので安心しよう。
有料の生成サービスやモデルの販売などモデル自体の商用利用は禁止だが、出力は商用利用ができる。
モデルの使用は、違法または悪意のある目的を除き自由。

高速化

Spectrum

https://github.com/AdamNizol/ComfyUI-Anima-Enhance...
チェビシェフの多項式を用いて出力を予測して高速化する。劣化が比較的少ない。

出力が常に変化するSDEソルバーでは効果がない。

ComfyUI内蔵の機能。出力をキャッシュして使い回す。
注意
出力が常に変化するSDEソルバーでは効果がない。
途中でコンディショニング(プロンプト)を変えても効果がなくなる。

DMD2

https://civitai.com/models/2466415/
蒸留LoRA。CFG1で使用する。EulerやRES MultistepなどのODEソルバーの使用を強く推奨。
多様性を著しく低下させるが、わずか4ステップで収束する。
注意
収束しないSDEソルバー(名前にancestralやsdeがつくもの)は非推奨。ただしSDEなのに収束するSA Solverは使える。
ネガティブプロンプトは使えない(無視される)。
Anima対応版のNegPiPで代用すること。
https://github.com/pamparamm/ComfyUI-ppm

DMD2の欠点は、画風と構図がほとんど変化しなくなる上フラットな絵になること。

Comfy Kitchen Attention

ComfyUIオリジナルのAttention最適化。AttentionをINT8で計算することで、INT8対応かつFP8非対応のGPUで少し高速化する。Sage Attentionと同等の速度が出せる。
FP8対応GPUでもSage Attentionをインストールする手間がなくなるのでおすすめ。
ModelAttentionBackendノードを使うか、コマンドライン引数に--use-ck-attentionをつけることで有効化する。

トラブルシューティング

画風が安定しない

ベースモデルは高品質な画像に加え、低品質な画像も学習しているためブレが大きい。
画風を安定させるならアーティストタグを使うのが手っ取り早い。
あるいは画風LoRAを作って適用する。学習は素直で、作ったLoRAを適用すればネガティブ無しでも画風が安定する。

背景が単調か汚い

短いプロンプトでは単調になるか、破綻する。
ベースモデルで多様性が高い上Text Encoderが賢いLLMのため、書いていないものは生成しない傾向が強い。
Danbooruタグに加えて自然言語(英語)で具体的に指示することをお勧めする。

黒帯か枠が出る

レターボックスとは関係がなくても、特定の単語を使うと発生する。
ネガティブにletterboxed, borderを入れるだけでは抑制は困難。
緩和策
ネガティブプロンプトにletterboxed, borderを入れて、ステップ数を26以上にしてノイズスケジューラにLinear Quadraticを使う。
Linear Quadraticは中盤まで出力を平均化するため帯が消えやすくなる。

指が破綻する(融合や数の誤り)

手のポーズを指定すると緩和される。指定しないと平均的な手を出しておかしくなるのかも。
AIは概念を理解できず、単に統計的に生成しているため解決することはおそらくない。あとはパラメータ数の限界かも。
LoRA含むFine-Tuningでも設定によっては破綻が増加する。

アップスケーリング(hires.fix)でアーティファクトが出る

ベースモデルのCosmos-Predictの仕様。
解像度を下げるか、Ultimate SD Upscaleなどでタイル生成をして回避する。
Anima Base V1.0は約320万画素がアーティファクトが出ない上限。

LoRA学習のヒント

LLM Adapterは学習NG
学習すると破綻が増加するとの報告がある。sd-scriptsのLoRA学習であれば明示しない限り、学習しない。
AdaLNは学習NG
学習すると品質が低下する。sd-scriptsのLoRA学習であれば明示しない限り、学習しない。
Text Encoderの学習は基本的に不要
TE無しでも品質に影響しない。それどころかTEの学習はプロンプト忠実度を下げるかもしれない。
SDXL以前のTEとは違い前の単語の効果が強い性質がないためシャッフル不要。
cache_text_encoder_outputsでTEの出力をキャッシュしてメモリを節約できる。cache_text_encoder_outputs_to_diskで二回目以降の学習準備が高速化する。
Timestep Sampling
この設定は難しいので弄るなら慣れてからにしよう。とりあえず初期値(timestep_sampling=sigmoid, sigmoid_scale=1)のまま弄らないことをおすすめする。

shift、flux_shift、sigma, sigmoidのいずれかを指定して使用する。sd-scriptsのデフォルトはsigmoid。
shift, sigmoidがよく使われている。
  • Discrete Flow Shiftの値
timestep_samplingの"shift"は、"sigmoid"にシフト式を適用したものでtimestepのサンプリング分布を偏らせる。
Timestep Sampling="shift"の場合のみ設定可能。生成で使用するFlow Shiftと同じ機能だが、Animaの推論時の初期値の3が最適とは限らないことに留意。
sd-scriptsのデフォルトは1.0。
shiftを使うのであれば、1.5から始めると良い。
1でシフトしない(sigmoidと同一になる)。1超過で低周波成分(構図)の学習が強くなる。1未満で高周波成分(細部)の学習が強くなる。
なお、Timestep Sampling="flux_shift"では無視される代わりに、画像解像度に応じたDiscrete Flow Shift値が採用される。
  • sigmoid_scale
timestep_samplingがsigmoid、shiftまたはflux_shiftの場合に設定可能。
sd-scriptsデフォルトである1.0のままでいい。
少し上げると、すべてのtimestepに対してまんべんなく学習できる。ただし最大でも1.5に留めた方がいいかも。
1で中央優勢の学習をする。1超過でTimestepの端部(構図と細部)の学習が強くなる。1未満で中央の学習が強くなる。

サンプル手法ごとの選択されるTimestepの分布

左がT=1000(完全なノイズ)で構図、右がT=0(完全な画像)でディティール側。
画像右の図はlossの倍率で、Flow Matchingでは一様なので気にしなくていい。
  • Sigmoid, Scale=1

中央優勢の無難な分布。
  • Sigmoid, Scale=1.3

  • Sigmoid, Scale=1.6

全体をまんべんなく学習する。ディティールを学習させるには1.5がよさそう。
  • Sigmoid, Scale=2

中央が少ない極端な分布で望ましくない。
  • Shift, Flow Shift=1

scale=1のsigmoidと同一。
  • Shift, Flow Shift=1.5

  • Shift, Flow Shift=2

  • Shift, Flow Shift=2.5

  • Shift, Flow Shift=3

ノイズ側(構図の影響が大きい)ばかり学習する一方でディティールをほとんど学習しない。
使用できないオプション(ノイズ関連)
Flow MatchingのAnimaは予測でノイズを扱わないため、以下のSNRやノイズ関連の設定は機能しない。指定してもエラーになるか無視される。
  • v-parameterization
  • Zero Terminal SNR
  • Debiased Estimation
  • Noise Offset
  • Multires noise iterations
  • Multires noise discount
  • Min SNR Gamma
  • Adaptive Noise Scale
  • huber scheduleにsnr指定
使用できないオプション
以下のオプションは使用できない。指定してもエラーになるか無視される。
  • 層別LR: SD1/SDXLの指定方法は無効。代わりに正規表現を使用すること
  • 層別Dim/Alpha
  • 畳み込み層(Conv)の学習: AnimaはTransformerベースであり畳み込み層が無い
