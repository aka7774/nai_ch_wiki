MOSS-Imageについて

https://openmoss.ai/MOSS-Image/
  • ユーザーガイド: https://github.com/OpenMOSS/MOSS-Image/blob/main/U...
OpenMOSS Teamが開発する、Text-to-ImageのMMDiTモデル。多様なスタイルに対応。

パラメータ数は5Bと現代のMMDiTモデルの中では比較的軽量な方で、VRAM8GBで動作する(だが計算はAnimaより約2.5倍大きい分遅い)。

長所

  • プロンプト忠実度がとても高い。
  • 版権キャラとNSFW対応。検閲なし。
  • 拡散モデルは比較的軽量(5B)なのに高品質。
  • プロンプトは英語以外にもDanbooruタグ、日本語や中国語などの多数の言語、Json形式が使える。
  • 文字の描写が優れている
拡散モデル
これは現在主流のTransformerベースのDiffusion Transformer(DiT)を採用する。シングルストリーム。
DiTは水平線や物体の構造の連続性維持が比較的得意で破綻が少ない。
パラメータ数は5Bと現代のMMDiTモデルの中では比較的軽量な方。なお、Animaは2Bでもっと軽く速い(その分低品質)。
TE
Text Encoderは、Qwen3.5-9Bでローカルのt2iモデルのTEとしてはかなり強い。位置や文字などの具体的な情報を解釈できる。
VAE
16チャネルのFLUX.2 VAEを使用する。Qwen Image VAEより良いらしい。

欠点

  • 計算が遅い。SDXLの二倍の時間がかかるAnimaの2.5倍の時間がかかる。
    • Krea2やFLUX.2よりは速い
    • INT8量子化などで高速化可能
  • TEが重い。
  • 対応UIがとても少ない。ネイティブサポートはComfyUIのみ。
  • リリース直後で知識も資産もほぼ無い。

対応UI

現時点でComfyUIと Forge neo（10月19日時点で拡張機能が必要）

動作要件

空き容量30GB以上のSSD推奨。
推論
32GB以上のRAMと最低8GBのVRAMを搭載するfp16対応GPU。bf16対応の12GB以上のVRAMを搭載したGPUを推奨。

使用方法(ComfyUI)

Comfy-OrgのHugging Faceリポジトリから次のファイルをDLして配置する。
https://huggingface.co/Comfy-Org/MOSS-Image/tree/m...

ComfyUI/models/diffusion_modelsにmoss_image_〇〇_int8_convrot.safetensors
〇〇はbase, sftのいずれか。baseは基本、sftは出力の品質向上と安定性向上を図ったもの。

ComfyUI/models/text_encodersにqwen3.5_9b_int8_convrot.safetensors
ComfyUI/models/vaeにflux2-vae.safetensors
ComfyUIのテンプレートの注意
ComfyUIのテンプレートには、プロンプトのアップサンプリングがついている。
プロンプトに不適切な内容があると実際のプロンプトが「すみません。その質問にはお答えできません。」になるので注意。
サブグラフのenable_prompt_upsamplerをオフにするとアップサンプリングをしない。

推奨生成パラメータ

  • 解像度: 推奨は1MP(1024x1024), 1.5MP(1280x1280,1024x1536), 2MP(1536x1536)。最小0.25MP(512x512)、最大4MP(2024x2048)。
  • Steps: 50
  • Guidance Scale: 3
  • Sampler: Euler
  • Scheduler: SGM Uniform

公式には書いていないがこれでも良い感じ。
  • Steps: 26-32あたりでも十分かも
  • Sampler: Gradient Estimationが無難。RES Multistep、ER SDE、SA Solverでもよい。
  • Scheduler: Linear Quadraticが無難。Simple、NormalやSGM Uniformは破綻が少し多くなる。
    • KarrasとExponentialは非対応(SDXL以前のepsilonモデル専用)。

モデルの種類

Base

https://huggingface.co/OpenMOSS-Team/MOSS-Image-Ba...
基本のモデル。多様性が高い分不安定。
不安定とはいえ、Anima Baseのように低品質な画像しか出ないということは無いので使い勝手は悪くない。
AIらしさが嫌か、多様な表現を求めるならこちらの方が良い。

SFT

https://huggingface.co/OpenMOSS-Team/MOSS-Image-SF...
美的チューニングを施した出力品質が安定したモデル。
安定するが表現の幅は狭い。マスピ絵、マスピ顔ばかりになる。

プロンプト

プロンプトはDanbooruタグと自然言語(多言語)とJson形式が使える。位置指定や文字描写などの具体的な命令もOK。
英文が苦手なら翻訳機で「これは~が~しているイラストです。~と~が背景にあります。このイラストは~な雰囲気です。」のような文章を英語にすればいい。チャットボットに考えてもらうのもいい。
それか日本語で入力する。
画像から自然言語プロンプトを生成するなら、検閲解除版のVLM(Gemma 4など)を使うと良い。

強度指定

非対応。TEにLLMを使用するモデルでは非対応なのが当り前。

Flow Shiftの値

ComfyUIのModelSamplingAuraFlowのshiftのこと。
低いほど高周波成分が強くなってディティールが増えるが不安定になる。高いほど安定するが、絵が平坦になる。
初期値は5。解像度に合わせて高くするといいかも。
ステップ数が多いほどこの値の影響が小さくなる。ノイズスケジューラにLinear Quadraticを選択しても影響が小さくなる。

SkipLayerGuidance

single_layersに22, 24, 26を指定すると破綻が減少するが、ディティールも減少する。
適用範囲(start_percentとend_percentで指定)が広いとディティールが過度に減少して不自然なスタイルになる。

高速化

DMD

Base用: https://huggingface.co/lodestones/MOSS-Image-Base-...
SFT用: https://huggingface.co/lodestones/MOSS-Image-SFT-8...
CFGの計算を不要にし高速化しつつ8ステップで収束させる蒸留LoRA。
注意
一般的な蒸留モデルと同様にCFG1、EulerなどのODEソルバーで使用する。
ネガティブプロンプトは使えない。出力の多様性を著しく低下させ、ややぼやけた画像になる。
さらに文字描画の精度が大幅に低下する。
